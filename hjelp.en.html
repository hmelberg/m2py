SafeStat

Analyse protected data without the data leaving safe ground.

What is this?

SafeStat is an analysis workbench in the browser for data that cannot be looked at directly. You write ordinary Python, R or SQL; SafeStat makes sure that only suppressed aggregates get out — never a single row, never an extreme value.

30 seconds

Choose python in the mode menu, paste this in, and press Ctrl+Enter:

Code py 
# options.profile = strict
df.groupby("kjonn")["lonn"].mean()
Result 
kjonn  mean(lonn)
1  520 790
2  518 450

You got a group mean. Now try df.head() instead — it doesn't exist, and Restricted Python explains why.

The trust model

Everything hinges on one question: where does your code run, and what is allowed to leave that place? A protected source decides the answer itself, no matter what you write in the script. For public data, the choice is yours — you can request the same strict facade yourself, before you've even connected to a protected source.

LevelWhere the code runsProfile in SafeStatRestriction
publicIn your browserOPEN, unless you request strictNone
protectedBehind the facade — locally if the owner has enabled it, otherwise only remotelySTRICT, alwaysRequires login; the run is logged
sensitiveSame as protectedSTRICT, alwaysSame as protected, and it can NOT be used with pull federation — it requires a node member

Mix several sources, and the most restrictive level wins.

By default, neither protected nor sensitive can be run locally — the owner must enable that per source. SafeStat always runs protected sources through the facade, no matter what you write — the app enforces this, not the library.

Two profiles

ProfileWhat's in the namespaceThe defense
OPENReal pandas and the raw data frameEnumeration: a gatekeeper on syntax nodes, a deny-list on methods, and a provenance check on the way out. "Probably safe" — the whole of pandas is the attack surface.
STRICTOnly the SafeFrame facade and the safe verbs. No pandas, no raw data frame.Construction: the revealing capabilities do not exist. The attack surface is the short, closed method list.
Turn it on yourself: # options.profile = strict at the top of the script, in python, r or duckdb mode. Protected sources force strict no matter what you write.

Protected sources

A protected source is encrypted on disk and is unlocked with a key you provide. The key is used to decrypt, never to send data out.

SourceUnlocked withWhere the key lives
Password-protected filePassword in the dialogIn memory only, gone on reload
Encrypted dataset (.enc)Key from the key storeThe key store in your browser — synced to your account if you're logged in
Federated nodeNode tokenOn the node — the data never leaves it

If you clear your browser data without having been logged in, the key is gone for good — an encrypted dataset cannot be unlocked again without it.

The key store is described under Key store.

Restricted Python

You write pandas. But in the STRICT profile, df is not a DataFrame — it is a SafeFrame, a facade with a deliberately short selection of methods. Everything that could show you a single row is not forbidden; it does not exist.

You want toWriteWorks
Look at the datadf.head()No — use df.describe() or df.count()
Group meandf.groupby("kjonn")["lonn"].mean()Yes
Filterdf[df["alder"] >= 40]Yes — the mask is legal, the result is still private
One rowdf["lonn"][0]No — positional indexing is closed
Regressiondf.ols("lonn ~ alder + kjonn")Yes
Custom expressiondf.apply(lambda r: …)No — arbitrary code is the actual risk

What works

Code py 
df.groupby("kjonn")["lonn"].mean()
Result 
kjonn  mean(lonn)
1  520 790
2  518 450

Three ways to get rejected

The gatekeeper reads your code before it runs. The messages name code — a method, a module, a line — but never a data value, since error text would otherwise be a leak channel.

Raw rows py 
df.head()
Result 
Avvist (attribute): 'head' is not allowed: it can reveal individual rows or run arbitrary code
Positional index py 
df["lonn"][0]
Result 
Avvist (subscript): positional indexing (df[<int>]) is not allowed; select by column name or boolean mask
Import outside the list py 
import os
df.groupby("kjonn")["lonn"].mean()
Result 
Avvist (import): module 'os' is not available in safepy

Columns

A column (SafeColumn) additionally has abs between cummax cummin cumprod cumsum diff dt ffill bfill interpolate isin isna notna kurt kurtosis map mask max min pct_change quantile sem shift skew str — and plot / hist / boxplot, where the histogram is redirected to a suppressed frequency table.

What's never allowed

CategoryExamplesWhy
Raw rows outhead tail sample iloc loc at iat values iterrows to_csv to_dict to_numpyShows individual units directly
Row-identifying reductionidxmax idxmin argmax nlargest nsmallest first last modeReturns one specific row
RankingrankRanking plus filter plus sum is a differencing-attack primitive. Requires a query budget that doesn't exist yet.
Arbitrary codeapply applymap pipe query eval rollingTakes a function; it can do anything
Sandbox escapeeval exec open getattr globals __import__Out of the sandbox
Syntaxlambda, comprehensions, def, for, while, try, f-strings, df[1:5]The gatekeeper only accepts assignments and expressions. New syntax can't sneak in.
Namesanything starting with _Private attributes are a detour around the facade

Only len round abs int float str bool can be called on names. Only lifelines numpy pandas pyfixest polars can be imported, and they resolve to safe facades — never the real modules.

Reshaping is allowed. pivot, stack, melt and explode keep the whole population and return a private object that can only leave the system as a suppressed aggregate. They are safe by construction, not by permission.

Restricted R

Your R code is translated — it is never run directly. SafeStat reads the expression, rebuilds it into the same release core that Restricted Python uses, and runs it there. So it isn't the whole of R you have access to, but a dialect: the tidyverse form of whatever can be expressed safely.

You want toWriteWorks
Group and summarisedf |> group_by(kjonn) |> summarise(m = mean(lonn))Yes
Filterdf |> filter(alder >= 40)Yes
New columndf |> mutate(logl = log(lonn))Yes
Look at the datahead(df)No
Regressionlm(lonn ~ alder + kjonn, data = df)Yes
Custom functionsapply(df, function(x) …)No — arbitrary code

Both the pipe operator |> and %>% are understood.

What works

Code r 
df |> group_by(kjonn) |> summarise(m = mean(lonn), n = n())
Result 
  m  n
1  520 790  2 530
2  518 450  2 470

What doesn't exist

Base-R functions that show rows are not part of the dialect. The message names which function is involved, not what was in the data.

Code r 
head(df)
Result 
Avvist (DisclosureError): base-R function 'head' is not supported in safepy's R dialect
Same core, same rules. Everything in Restricted Python's "What's never allowed" applies here too — just expressed in R. Ranking, row-identifying reductions and arbitrary functions are closed for the same reason.

Restricted SQL

SQL is the third dialect into the same core. Unlike R, SQL is actually run — but only after a static gatekeeper that reads the parsed query before anything executes, in a locked DuckDB engine with no file or network access, and everything gets out through the same suppression core that the pandas and R dialects use. SELECT with GROUP BY works; anything that would return rows does not.

Code sql 
SELECT kjonn, avg(lonn) AS m, count(*) AS n
FROM df GROUP BY kjonn ORDER BY kjonn
Result 
  m  n
1  520 790  2 530
2  518 450  2 470
ConstructWorks
SELECT … GROUP BY with aggregate functionsYes
WHERE filtersYes
JOIN between sources at the same levelYes
ORDER BY on a GROUP BY keyYes — and worth using: without it, row order is arbitrary
ORDER BY on an aggregateNo — it would reveal exact, unrounded values
SELECT * without aggregationNo — that's rows
LIMIT to fetch individual rowsNo — same rule as SELECT *: every item must be a group key or a safe aggregate
ORDER BY followed by row fetching (the classic min/max trick)No — stopped by the rule above, before LIMIT even gets to run

Pseudonym variables

Variables that identify units (typically variables with names ending in _FNR — e.g. BEFOLKNING_MOR_FNR) are pseudonyms. In microdata.no these can only be used as a key in collapse(by) or merge(on) — not in generate/replace, comparisons or other transformations.

Control flow

For loops use the prod grammar: a range with n : m (inclusive), or a value list (comma- or whitespace-separated). Use $i for substitution. Do not use parentheses around the iterator list or a literal ellipsis ....

for i in 2018 : 2020
  import db/INNTEKT_WLONN $i-01-01 as inntekt_$i
end

for forelder in mor, far
  // ...
end

let maks = 200000
generate hoy = (inntekt > maks)

Disclosure control

m2py emulates microdata.no's rules by default — both syntax/validation (so your script runs in prod) and suppression of output (so you see the same numbers as in prod). You can turn everything off in the hamburger menu ("Disclosure control: OFF") to experiment without restrictions, but then you risk writing scripts that won't run in microdata.no. Specific rules:

  • Pseudonym validation. Variables ending in _FNR can only be used as a key in collapse(by) or merge(on) — not in generate, replace, comparisons, etc.
  • Type check. Alphanumeric variables (e.g. BEFOLKNING_KJOENN) are rejected for numeric operations such as min, max, mean, sum, median.
  • For loops: use $i substitution and either a range (1998 : 2009) or a comma/whitespace list. Parentheses around values and a literal ... are not valid.
  • Missing values. Assignment with . is OK (generate x = .). Comparison with ., however, is not valid — keep if y == . is rejected in microdata.no. Use sysmiss(y) to test whether a value is missing.
  • Minimum population 1000. keep if, drop if and sample cannot leave fewer than 1000 units.
  • Tables with too many small cells are suppressed. tabulate is blocked if more than 50% of the cells have a frequency lower than 5.
  • Changes must affect ≥10 units. generate, replace and recode are rejected if the change affects 1–9 rows (or all except 1–9).
  • Descriptive statistics require ≥10 units. summarize, correlate, ci, anova, normaltest are blocked for populations under 10.
  • Median/percentiles are shown with 3 significant digits. In summarize, for example, 47,238 becomes 47,200 and 2.7183 becomes 2.72.
  • Winsorization 1/99%. Numeric variables are capped at the 1st and 99th percentile before displaying the mean and standard deviation in summarize, and before plotting in histogram, scatter and boxplot. The median and quartiles are not affected. Regression and collapse use raw data.

Per-script override

You can also control disclosure control from within the script itself with a magic directive at the top of the code. The directive is an ordinary comment (//) that is ignored by microdata.no production, but is read by m2py before execution and switched back afterwards (does not affect other scripts):

// m2py: disclosure-control=off
create-dataset bef
import db/BEFOLKNING_KJOENN as kjonn
summarize kjonn

Values: on/off, true/false, 1/0, yes/no. The short form dc is also accepted: // m2py: dc=off. Useful in API/script usage where you want to control the mode without changing global settings.

Data minimisation assessment

m2py can ask an AI to assess whether your script practices data minimisation — the principle of retrieving and using only the minimum amount of data needed for the research question. The feature is advisory; the final assessment rests with the researcher and data controller.

The assessment is grounded in:

  • GDPR Art. 5(1)(c) — data minimisation
  • Norwegian Health Registry Act (Helseregisterloven) § 6 — degree of personal identification
  • GDPR Art. 89(1) — scientific research
  • GDPR Art. 9 — special categories (sensitive data)

How it works

Click the hamburger menu → "Assess data minimisation". The first time you use the feature, a confirmation is shown that the script is sent to Anthropic. Actual microdata values are never sent.

In the options modal you can:

  • Choose language (auto / microdata / R / Python) — auto detects from the script
  • Choose report length: Short (quick observations) or Long (all dimensions with follow-up questions)
  • Request a revised script — the AI appends a conservative revised version at the end of the answer, which you can copy or replace the editor with
  • Specify purpose and context — optional; gives a more precise assessment

Login

The AI assessment requires that you are logged in to m2py. Use the Log in button at the top and follow the link in the email. Once you are logged in (via an FHI or other approved email address), you have access to the data minimisation feature automatically — no separate access key is needed.

Sensitive variables

The AI automatically flags variables that fall under special categories (GDPR Art. 9): ethnicity, religion, sexual orientation, particularly sensitive health information (abortion, sexually transmitted diseases, psychiatry, etc.), and legal/criminal records. These require a higher justification threshold.

Privacy comments in the script

You can add structured justifications directly in the script: 

// personvern blokk start
// purpose: Study the relationship between education and income
// time period: 1970-1980 because the cohort should have completed education
// geography: municipality needed to see regional differences
// sensitive groups: no
// alternatives considered: SSB table A-04 was too coarse-grained
// personvern blokk slutt

Or free text: 

// personvern blokk start
// Purpose: study the relationship between education and income for the 1970-1980 cohort.
// The time period was chosen because the cohort should have completed education by the end of the analysis.
// Municipality needed for regional differences.
// personvern blokk slutt

If you check "Save as privacy block" in the secondary modal, m2py writes the content into the script automatically after the assessment.

Single lines also work: 

// personvern: dates truncated to month to avoid unnecessary precision

You can also use # instead of // in Python/R scripts.

Directives in the script

You can control the AI behavior directly in the script: 

// personvern: revider-script: ja

This makes the AI turn on revised-script output regardless of what you choose in the UI. Useful if you have a template that should always be revised.

Editor

Save, share and fetch scripts

All the options below are in the hamburger menu at the top left. They run entirely in your browser — we never store your scripts on a server.

Download code / Load file

Download code downloads the script as a .txt file to your machine. Load file (local) opens such a file again. This is purely local file handling.

Share (copy link)

Creates a link that contains the entire script, compressed into the address itself (after #). The link is copied to the clipboard — send it by email, Slack, or paste it wherever you like. Whoever opens the link gets the script directly into the editor.

  • Nothing is stored with us, and the recipient does not need to log in.
  • The link is a frozen snapshot — if you change the script afterwards, you must share a new link.
  • Suitable for scripts up to a few thousand characters. If the script is too large for a URL, you'll be notified — use "Download code" (file) or GitHub instead.

Open from URL

Paste a direct link to a text file, and the content is fetched into the editor. The most recent URLs you've used are remembered locally for quick reopening.

  • Works with GitHub "raw" links, GitHub gist (raw) and Dropbox.
  • Regular share links (e.g. a Google Drive or GitHub page) do not work — you must use the raw file link. If you get an error message, it's almost always because the source doesn't allow direct fetching (CORS).
  • The file extension controls the mode: .py → Python, .r → R, otherwise the default mode.

GitHub (advanced)

Lets you save and fetch scripts directly in your own GitHub repo — with version history and the ability to collaborate. Everything is under the GitHub submenu in the hamburger menu.

1. Settings (one-time). Fill in a personal access token (PAT), repo (owner/name) and branch. Press Test connection to confirm, and Save settings. The information is remembered locally in the browser. You do not need to specify any file path here — you're connecting to the repo, not a single file.

Multiple profiles. If you have several repos or accounts (e.g. work and personal), you can save them as separate profiles and switch between them in the dropdown at the top of the dialog ("New" to add, "Delete" to remove). The selected profile controls Open/Save. With Show and Copy you can view or copy the token — useful when setting up the same profile on another machine.

How to create a token: GitHub → Settings → Developer settings → Fine-grained tokens → Generate new token. Give it access to only the relevant repo, and set Repository permissions → Contents → Read and write. Copy the token (shown only once) and paste it into the app. Feel free to set an expiry date; you can revoke the token at any time on the same page.

2. Daily use. Once the connection is set up:

  • Open file… shows a file picker with all the files in the repo. Filter in the search field and click a file to fetch it into the editor.
  • Save writes to the file you last opened or saved (the current file, marked with a cloud symbol ☁ next to the script name). If you don't have a current file yet, it behaves like "Save as". If you open a new or different script (New, local file, example, link or URL), the cloud symbol is disconnected so you don't accidentally overwrite the wrong file.
  • Save as… lets you type a new file path (existing folders are suggested). The .txt extension is added automatically if you don't type one.
  • Refetch fetches the current file again from GitHub (reads — does not save). Unsaved local changes are lost, so you'll be asked to confirm.
  • One token, many files: the token applies to the whole repo — you don't need a token per file.
  • Public vs. private is controlled via the repo's own setting on GitHub — not in the app.
  • Sharing: if the script is in a public repo, you just share the raw file link; the recipient uses "Open from URL".
  • The token is a secret and is stored in plain text in your browser. Use a shared machine with care, and revoke the token if you lose access to the machine.

Recently used

A small down-arrow icon (▾) next to the filename shows the most recent GitHub and URL scripts you've opened, so you can fetch them again with one click without typing the whole address. (Local files cannot be reopened by the browser.)

Where is everything stored — and does it work on multiple machines?

It's useful to distinguish the file from the machine:

  • Scripts stored in GitHub live in the cloud and are accessible from anywhere. On a new machine you just paste in the same token once (or nothing if the repo is public — then you use "Open from URL").
  • Share links carry the script within themselves and work on any machine.
  • What is tied to one machine is only local things in the browser: the list of "recent URLs" and the pasted-in GitHub token. Your actual scripts in GitHub are not locked to the machine.

Run step by step — a step-by-step walkthrough

Run step by step runs the script one block at a time and reads the comments aloud using speech. Comment lines — those starting with # or //, depending on which comment character the mode uses — are read aloud; the code lines are executed without commentary. Useful for presentations and teaching.

Blocks

A block is a group of consecutive lines with no blank lines between them. One or more blank lines separate blocks.

# This comment is read ALOUD before the code runs
df["alder"] = 2024 - df["fodselsar"]

# This is the next block
df.groupby("kjonn")["lonn"].mean()
# This comment is read after the result is shown

Comment syntax

SyntaxEffect
# text / // textRead as speech; a leading comment is read BEFORE the code, a trailing one is read AFTER
#- / //-Silent comment — the first code word is not read aloud, and text after - is not read either
//(lang=nb-NO,rate=1.2) textSpeech with custom parameters (language, rate, voice, pitch)

Pause, navigation and breakpoints

  • Press Run step by step again to pause/resume
  • The arrow buttons jump to the previous/next block
  • Breakpoints (click a line number) make the run pause automatically

Widgets in Run step by step

Widgets are interactive cards shown while the script runs step by step. They are inserted as special comment lines and are available in all modes.

Syntax

#widget NAME { ...json... }

The comment character follows the mode: # in most modes, // in modes that use it as the comment character — both are interpreted the same way.

Block syntax for longer content

For HTML, SVG and markdown with multiple lines, you can use block syntax instead of JSON:

//start_widget:html(title="Example", speak="Here you see HTML content.")
<div style="text-align:center">
  <h2>Hello from HTML</h2>
  <p>Multiple lines without escaping.</p>
</div>
//end_widget

Available widgets

WidgetExampleDescription
title //widget title {"text":"Chapter 1","size":"full"} Large title card with animation. size: "full", "medium", "small"
markdown //widget markdown {"text":"# Hello\nThis is **bold** text"} Rendered Markdown content

AI assistant

An experimental side panel with an AI assistant that can answer questions about syntax, suggest variables, and generate or revise scripts. Opened with the star icon at the top right or Ctrl+I.

Requires an API key. Click the gear icon in the AI panel to set it up. The key is stored only locally in the browser (localStorage).

What the assistant can do

The assistant classifies the question and answers in one of three ways:

  • Question — explains commands, syntax and usage ("What does this function do?")
  • Variable search — finds relevant variables in the data catalogue ("What variables exist for education?")
  • Script generation — creates a complete script from a natural-language question ("Show summary statistics for income and gender")

Revising an existing script

To let the assistant modify the script in the editor, you must check "Include script from editor (revise)" right above the text field before sending. This uses the content of the editor as a starting point, and the request is interpreted as a revision — for example "Add log income" or "Filter on age over 25".

Without this checkbox checked, a new script is created from scratch, even if the editor has content.

Buttons on generated scripts

When the assistant returns a script, three buttons are shown under the code block:

  • 📋 Copy — copies the script to the clipboard
  • ⬇ Replace script — replaces everything in the editor with the generated script
  • + Add — appends the script to the bottom of the editor

Validation warnings

Generated scripts are run through static validation before being shown. If there are unknown variables, unknown commands or parsing errors, these are shown as clickable chips under the script. Click a chip to compose a follow-up message asking the assistant to fix that specific error.

Time usage

Questions and variable searches usually respond in under 5 seconds. Script generation and revision can take 20–60 seconds, up to ~3 minutes for complicated requests — you'll see a "Thinking… Ns" counter while the job runs in the background.

Other controls

  • Gear icon — change API key and other settings
  • Trash icon — clear the conversation (does not delete anything on the server)
  • × — close the panel
  • Enter sends, Shift+Enter inserts a new line

Privacy

What is sent to the API is only your question text, and — if checked — the content of the script editor. Data files, run results, output and widget content are not sent. Norwegian or English language is guessed automatically from the question.

Experimental. The AI assistant can be wrong, suggest variables that don't exist, or generate scripts that don't run. Always check the result before use.

How to get a key in SafeStat

Log in, or paste in your own Anthropic key (created at console.anthropic.com) under "Or use your own Anthropic API key" in settings — usage is then billed to your own account. Under "Advanced" you can additionally set a service token that is sent as X-API-Key to the app's Anvil backend; it is meant for script/automation use, not ordinary chatting.

Modes

Choose a language from the dropdown menu in the bottom bar, or use mode-switch lines in the script to switch along the way (see Hybrid scripts).

Next to the language selector, two badges show the session's security level and compute location. The level is derived automatically from the sources in the script and cannot be overridden — green Open (no protected sources), amber Restricted (strict profile or a protected source: only aggregated results are released), dashed amber Unknown (a source we don't recognize — log in to see the level), purple Encrypted (a homomorphically encrypted source: only group_agg / value_counts / crosstab / ols). The location badge shows Local (in the browser) or Server; when both are possible you can click the badge — the choice is written as exec(local|remote) into the script, so the script always remains the source of truth. Sharing data between languages: # use

Microdata and Python blocks share datasets automatically (same engine). Between different engines — Python↔R, microdata→R, DuckDB↔others — fetch a dataset explicitly with a use line at the top of the block:

#py
df["ny"] = df["x"] * 2

#r
# use df
summary(df$ny)

Without from, the dataset is fetched from the nearest earlier block in a different language; specify # use df from python|r|duckdb when needed (required when the source is a previous run). Copy semantics: the block gets a snapshot — changes do not propagate back to the source engine.

Example: microdata + Python

## microdata
require no.ssb.fdb:52 as db
create-dataset df
import db/BEFOLKNING_FOEDSELS_AAR_MND as faarmnd
import db/INNTEKT_WLONN 2022-01-01 as inntekt
generate alder = 2022 - int(faarmnd / 100)
keep if inrange(alder, 25, 67)
keep if inntekt > 0

## python
import matplotlib.pyplot as plt
df.plot.scatter(x="alder", y="inntekt", alpha=0.3, s=8)
plt.tight_layout()
show(plt.gcf())

Federated sources

Sometimes the data can't be moved — it sits with several owners, each allowed to see their own, but no one allowed to see all of it. A federated source is one dataset that sits split across several data holders (same variables, different people — e.g. one file per region). You write the script as if the data were pooled; SafeStat does the rest. Two tiers:

Pull — the files are fetched and combined

Members are ordinary files (optionally encrypted). They are fetched, unioned automatically, and the __member column shows which member each row came from. Works in every mode:

# connect demo-federert as helse
# load helse as personer
print(personer["__member"].value_counts())

Custom: # connect federert(https://a.no/data, https://b.no/data) as h + # load h/person.parquet as df. Column names must agree across all members, or the run is refused. Sensitive members are refused in pull — they require nodes.

Nodes — the script travels, the data stays

Members with tier: "node" run the script locally on their end and only release SDC-protected aggregates; the browser combines them (microdata mode, require ... as ...). Verbs other than the four below are refused with a clear message, and one member being down stops the whole run. A script can today only require one federated target:

require demo-federert-node as person
create-dataset person
tabulate BEFOLKNING_KJOENN
logit kvinne BEFOLKNING_INNALDER

Two require lines against federated sources in the same script get SafeStat's response: "Federated execution supports one require target per script (for now)."

A data holder starts their own node with pip install ./node and safestat-node --config node.json (optional token; the app then asks per run). See the examples menu for runnable examples in python and microdata mode.

VerbWhat the node computesExact across nodes
tabulateCount per cellYes — the cell counts are summed
summarizeCount, mean, std, min and max per groupYes for mean, std, min and max — but percentiles (median, p1/p25/p75/p99) are never sent back from the node
regressCross-product matrices (XᵀX, Xᵀy)Yes — the normal equations are solved centrally from summed matrices
logitGradient and Hessian, one round per Newton iterationYes, but requires several round trips between nodes and browser — not a single combination step like the other three

"Exact" means the answer matches what you would have gotten if all the data sat in one table — confirmed by testing against a run on the pooled table (within ordinary floating-point precision), not just assumed.

What doesn't exist yet

MissingConsequence
Trusted hubNo intermediary that can see partial results before SDC. Everything is coordinated by your client, and a small cell is suppressed per node even if the sum across nodes would have been large enough to pass.
overlap handlingYou can mark a source overlap="possible" and get a visible warning in the result that counts are at the episode level, not the individual level. But SafeStat never deduplicates individuals across nodes, and there is no function to ask how many exist in several nodes at once.
Percentiles / medianSilently dropped in federated summarize — the result only shows mean, std, count, min and max.

Key store

Encrypted datasets need a key. The key store holds yours in the browser, so you don't have to paste the same key in every time. If you're logged in, the store is also synced to your account.

Three policies — and only two of them hide the key

Every key has a policy. This is the single most important choice in the whole store, because it decides whether the server can read your key.

PolicyHow it's storedHow often you enter a passwordCan the server read it?
open (default)Plaintext — no encryptionNeverYes, if you sync
lockedAES-256-GCM under the master passwordOnce per sessionNo — ciphertext only
secretSame as lockedOnce per run; never cachedNo — ciphertext only
The default is plaintext. open exists so things are frictionless, and for an API key you don't care about, that's fine. But if you add a key that unlocks protected data, choose locked or secret — otherwise it sits unencrypted in the browser, and is synced readable to the server if you're logged in.
ActionWhere it happens
Unlock a datasetIn the browser, after the key has been fetched from the store. The contents of the dataset are never sent out.
Unlock the storeThe master password derives a key that lives in memory only — never in sessionStorage. On reload you have to enter it again.
Sync between devicesThe whole document is synced as-is, if you're logged in. locked and secret entries are ciphertext; open entries are not.
If you lose the master password, the locked and secret keys are gone. The server cannot recover them — that's the whole point. open keys survive, precisely because they were never protected.
